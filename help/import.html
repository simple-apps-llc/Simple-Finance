Import

CSV, OFX, Excel, and reading a statement from a photo. 5 answers.

I imported my bank transactions but my account balance didn't change

Two things have to be true, and each one is easy to miss because the app does something reasonable without them.

1. THE TRANSACTIONS MUST BE ASSIGNED TO THE ACCOUNT. On the import screen there is an “Import into” picker. It now starts on your default account, but if it is set to “No account” the rows still import — they just belong to no account, so no balance can follow them. Fix an import you already did from Transactions: select the rows and set the account.

2. THE ACCOUNT MUST TRACK ITS BALANCE. Open the account and check “Track balance from transactions”. New checking, savings and cash accounts turn this on for you. When it is OFF the balance is a number you type and nothing changes it — which is right for a house or a car, and wrong for a current account.

With both on, the balance is your starting balance as of the tracking date, plus every assigned transaction after it. That figure is what Net Worth shows.

One thing that is NOT a fault: your opening balance does not appear in Year in Review or in spending totals. It is a starting position, not income — money you already had rather than money that came in.

How do I import existing accounts or transactions?

The Import tab reads accounts and loans from a photo or CSV and auto-classifies them for review before anything is saved. You approve the results — nothing imports silently.

What files can I import?

CSV and TSV from almost any bank or app, OFX and QFX from a bank download, Excel workbooks (.xlsx), and a photo or PDF of a statement read by OCR.

The file does not have to be tidy. Columns are matched by what is IN them rather than by their headings, so a file whose date column is called “Posted” and whose amount column is called “Debit” works without renaming anything. Dates in almost any order, amounts in parentheses, a trailing minus, currency symbols and thousands separators are all understood.

Apple Numbers' own .numbers format is not supported — export it as CSV or Excel first, which Numbers does in two clicks.

Everything is review-first. You see every row, and nothing is written until you say so.

My import shows odd characters like “café”. Why?

That's a file saved in an older text encoding. The app tries the common ones in order and should read it correctly — if a file still looks wrong, send it to us through Report a Problem and we'll fix the reader.

Will importing create duplicates?

It works hard not to. Rows matching something already in your ledger — same date, same amount, same account — are flagged during the review step, and you decide whether they are one charge or two identical ones.

Two $4.50 coffees on the same day at the same shop is a real thing that happens, which is why it asks rather than silently dropping the second.

If duplicates do get through — usually from importing the same file twice, or restoring a backup on top of live data — Settings → Data & Backup → Repair Duplicated Records finds them and shows you what it found before removing anything.
